Quickstart

Build the video card once with Flask: register at startup, write a nested partial, call it from a page, and know what the rendered output should look like.

Remember the fourteen video cards from Why partials? This page builds one, properly, with Flask. Every other framework differs only in the registration line, and Frameworks has those. Four files and a few minutes.

1. Register once at startup

# app.py
import flask
import jinja_partials

app = flask.Flask(__name__)
jinja_partials.register_extensions(app)


@app.get('/')
def index():
    return flask.render_template('home/index.html', videos=get_videos())

That one line installs render_partial as a global in the app’s Jinja environment. Do it where the app is built, before it starts serving, and do it once. There is no need to import anything in your templates; the function is simply there, like url_for.

2. Give the partials a home

Partials are ordinary templates, so they can live anywhere your loader can see. The convention this project uses, and the one the examples follow, is a partials folder under templates/shared:

templates/
├── home/
│   └── index.html
└── shared/
    ├── _layout.html
    └── partials/
        ├── video_image.html
        └── video_square.html

When you call render_partial, the name you pass is the path relative to the templates root, forward slashes and file extension included, exactly as you would write it for render_template. Nothing clever, which is the point.

3. Write the partials, smallest first

The innermost fragment is the YouTube thumbnail. It takes a video and an optional list of CSS classes:

<!-- templates/shared/partials/video_image.html -->
<img src="https://img.youtube.com/vi/{{ video.id }}/maxresdefault.jpg"
     class="img img-responsive {{ (classes | default([])) | join(' ') }}"
     alt="{{ video.title }}"
     title="{{ video.title }}">

Notice classes | default([]). The fragment declares that classes is optional by handling its absence itself. Callers that do not care never have to know it exists.

Now the card. It wraps the thumbnail in a link, adds the author and the view count, and it does so by rendering the image partial inside itself. Partials nest; that is half their charm.

<!-- templates/shared/partials/video_square.html -->
<div>
    <a href="https://www.youtube.com/watch?v={{ video.id }}" target="_blank">
        {{ render_partial('shared/partials/video_image.html', video=video) }}
    </a>
    <a href="https://www.youtube.com/watch?v={{ video.id }}" target="_blank"
       class="author">{{ video.author }}</a>
    <div class="views">{{ "{:,}".format(video.views) }} views</div>
</div>

4. Call it from a page

<!-- templates/home/index.html -->
{% extends "shared/_layout.html" %}
{% block main_content %}
    {% for v in videos %}
        <div class="col-md-3 video">
            {{ render_partial('shared/partials/video_square.html', video=v) }}
        </div>
    {% endfor %}
{% endblock %}

The page calls the loop variable v. The card calls it video. That renaming at the boundary is not a workaround; it is how partials are meant to be used. The fragment names what it needs, and each caller maps its own data onto those names. The listing page, the search results, and the email digest can all call this one file with whatever they happen to have.

5. What you should see

Run the app and open the page. Each video renders as a card like this, with the thumbnail inlined where the nested render_partial call used to be:

<div class="col-md-3 video">
    <div>
        <a href="https://www.youtube.com/watch?v=abc123" target="_blank">
            <img src="https://img.youtube.com/vi/abc123/maxresdefault.jpg" class="img img-responsive " alt="Intro to Flask" title="Intro to Flask">
        </a>
        <a href="https://www.youtube.com/watch?v=abc123" target="_blank" class="author">Talk Python</a>
        <div class="views">12,500 views</div>
    </div>
</div>

If instead the page shows you the HTML itself as text, angle brackets and all, the fragment was inserted as an escaped string rather than as markup. On Flask that does not happen, but on the plain Jinja2 path it is the single most common surprise, and Troubleshooting has the one-word fix along with every other error you are likely to meet.

The complete version of this app, with the layout, the CSS, and a small JSON database of videos, is the Flask example in the repository. It is the app behind the screenshot on the README.
